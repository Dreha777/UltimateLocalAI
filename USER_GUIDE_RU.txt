ULTIMATE LOCAL AI — РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ

Разработчик: Dreha777

1. НАЗНАЧЕНИЕ
Ultimate Local AI предназначена для локального запуска GGUF-моделей искусственного интеллекта в Windows через llama.cpp. Основная задача программы — дать единый графический интерфейс, который самостоятельно определяет аппаратные возможности компьютера, выбирает совместимый backend и подбирает рабочие параметры без обязательной ручной настройки.

2. ЧТО РАБОТАЕТ АВТОМАТИЧЕСКИ
В режиме Backend = Auto программа определяет:
- поддержку CPU AVX и AVX2;
- число логических процессоров;
- общий и свободный объём RAM;
- NVIDIA GPU через nvidia-smi, включая VRAM и compute capability;
- AMD/Intel/другие видеоадаптеры через Windows;
- наличие упакованных CUDA/Vulkan/CPU runtime.

Приоритет:
1) совместимый CUDA backend для NVIDIA;
2) Vulkan backend для поддерживаемых AMD, Intel и иных GPU;
3) CPU AVX2;
4) CPU AVX.

Также автоматически выбираются context, число потоков, batch/ubatch и GPU layers. При недостатке RAM параметры уменьшаются, чтобы снизить вероятность интенсивного использования файла подкачки.

3. ПЕРВЫЙ ЗАПУСК
1) Запустите UltimateLocalAI.exe.
2) Нажмите «Выбрать GGUF».
3) Выберите файл модели с расширением .gguf.
4) Оставьте Backend = Auto и Runtime = Stable, если нет причины менять их.
5) Нажмите «Запустить».
6) Дождитесь «Модель готова».
7) Введите сообщение и нажмите Enter.
Shift+Enter создаёт новую строку.

4. STABLE / LATEST / CUSTOM
Stable — проверенный runtime llama.cpp.
Latest — более новый runtime для новых GGUF-архитектур и GPU.
Custom — пользовательская папка runtime.
Auto может автоматически использовать упакованный Latest backend, если подходящего backend нет в Stable.

5. ВЫГРУЗКА МОДЕЛИ
Нажмите «Выгрузить». llama-server будет остановлен, а занятые моделью RAM/VRAM освобождены.

6. GPU
В Portable могут находиться:
- cuda-pascal-avx — NVIDIA Pascal sm_61;
- cuda-modern-avx2 — NVIDIA Turing/Ampere/Ada;
- cuda-blackwell-avx2 — NVIDIA Blackwell;
- vulkan-avx — Vulkan на CPU с AVX без AVX2;
- vulkan-avx2 — Vulkan на CPU с AVX2.

Если выбранный GPU backend не запускается и разрешён Auto fallback, программа переходит на CPU.

7. СЛАБЫЕ И СТАРЫЕ ПК
Оставьте Auto. Программа учитывает реально свободную RAM перед загрузкой модели. Для систем с малой памятью уменьшаются context и batch. AVX-only процессоры получают отдельный совместимый backend.

8. ЧАТ
«Новый чат» создаёт новую беседу.
История хранится локально в Data\chats.json.
Ответ генерируется потоково, а интерфейс обновляется пакетами, чтобы не зависать на каждом токене.

9. ВЛОЖЕНИЯ И БАЗА ЗНАНИЙ
Кнопка «＋» добавляет поддерживаемый локальный файл к запросу.
«База знаний» управляет локальными материалами, используемыми программой.

10. ТЕМА ИНТЕРФЕЙСА
В настройках доступны светлые, тёплые, холодные и очень тёмная темы. Выбранная тема сохраняется.

11. МОНИТОР РЕСУРСОВ
Слева отображаются CPU, RAM, GPU/VRAM и, для NVIDIA, температура GPU.

12. ЛОГИ
Logs\localai_YYYYMMDD.log
В лог записываются выбранный backend, параметры Auto Runtime, запуск llama-server, этапы загрузки, GPU offload (когда runtime его сообщает), тайминги и ошибки.
При проблеме закройте программу и передайте последний лог целиком.

13. ФАЙЛЫ ДАННЫХ
Data\config.json — настройки.
Data\chats.json — история чатов.
Data\knowledge.json — локальная база знаний.
Logs\ — диагностические журналы.

14. ПОРТАТИВНОСТЬ
Готовой Portable-сборке не нужны Visual Studio, .NET SDK, CMake, CUDA Toolkit или Vulkan SDK. Для GPU необходим актуальный системный драйвер соответствующего производителя.
