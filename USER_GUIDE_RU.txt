ULTIMATE LOCAL AI — РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ

Разработчик: Яхлов Андрей Васильевич

1. НАЗНАЧЕНИЕ
Ultimate Local AI предназначена для автономного локального запуска GGUF-моделей искусственного интеллекта в Windows через llama.cpp.

Проект создан по личной инициативе разработчика для рабочих условий, где интернет отсутствует или ограничен, а компьютеры могут быть сравнительно маломощными или сильно отличаться по конфигурации. Основная задача — единый графический интерфейс, который сам определяет аппаратные возможности ПК, выбирает совместимый backend и подбирает рабочие параметры без обязательной ручной настройки.

2. ПЕРВЫЙ ЗАПУСК
1) Распакуйте Portable в отдельную папку.
2) Запустите UltimateLocalAI.exe.
3) Нажмите «Выбрать GGUF».
4) Выберите локальный файл модели .gguf.
5) Оставьте Backend = Auto.
6) Нажмите «Запустить».
7) Дождитесь состояния «Модель готова».
8) Введите сообщение и нажмите Enter. Shift+Enter создаёт новую строку.

3. АВТОМАТИЧЕСКИЙ РЕЖИМ
Auto определяет:
- AVX/AVX2;
- число логических CPU;
- общий и свободный объём RAM;
- NVIDIA GPU, VRAM и compute capability через nvidia-smi;
- AMD/Intel/другие видеоадаптеры через Windows;
- наличие упакованных CUDA/Vulkan/CPU runtime.

Приоритет:
1) совместимый NVIDIA CUDA;
2) Vulkan;
3) CPU AVX2;
4) CPU AVX.

Автоматически выбираются context, threads, batch/ubatch, GPU layers и точность KV-cache.

Начиная со Stage 7E Auto работает по принципу quality-first:
- нормальная цель context — не менее 4096;
- context=2048 используется только при реальном дефиците памяти;
- Auto больше не опускает контекст до 1024;
- KV-cache использует f16 при достаточном запасе RAM/VRAM, иначе q8_0;
- q4 KV-cache автоматически не выбирается;
- до запуска из заголовка GGUF читаются квантование, архитектура, родной предел context и рекомендованные sampler-параметры, если модель их содержит;
- после запуска из /props llama-server читаются фактический context, chat template и его capabilities;
- рекомендованные sampler-параметры GGUF применяются только к настройкам, которые пользователь не менял вручную;
- для reasoning-моделей автоматически резервируется больший лимит ответа;
- при переполнении диалога сначала удаляется самая старая история, а текущий запрос сохраняется.

4. МЕНЕДЖЕР МОДЕЛЕЙ
Кнопка «Модели» открывает локальный каталог GGUF.
Можно добавить одну или несколько папок; программа рекурсивно находит *.gguf и читает метаданные без загрузки весов модели в RAM/VRAM.

Для каждой модели показываются:
- размер файла;
- архитектура и size label, если они записаны в GGUF;
- реальный тип квантования;
- родной context, если он записан в GGUF;
- оценка качества квантования;
- ориентировочная совместимость с доступной RAM/VRAM;
- рекомендация для этого ПК.

Оценка памяти является ориентировочной: реальный расход зависит от архитектуры модели, context, KV-cache, backend и доли GPU offload. Менеджер не сравнивает «интеллект» разных архитектур по одному размеру файла.

Профили Auto:
- «Качество» — профиль по умолчанию: максимальный разумный context, F16 KV при достаточном запасе памяти и увеличенный лимит ответа;
- «Баланс» — умеренный context/batch и q8_0 KV;
- «Экономия» — context 2048–4096 и меньший batch для слабых ПК.

Выбранный профиль сохраняется. Ручные настройки пользователя продолжают иметь приоритет там, где они заданы явно.

5. STABLE / LATEST / CUSTOM
Stable — зафиксированный проверенный runtime llama.cpp.
Latest — более новый runtime для новых GGUF-архитектур и GPU.
Custom — пользовательская папка runtime.

6. BACKEND
В полной Portable предусмотрены:
- cpu-avx;
- cpu-avx2;
- cuda-pascal-avx;
- cuda-modern-avx2;
- cuda-blackwell-avx2;
- vulkan-avx;
- vulkan-avx2.

Vulkan служит универсальным GPU fallback для AMD, Intel и иных совместимых адаптеров, если подходящий CUDA backend отсутствует.

7. СЛАБЫЕ И СТАРЫЕ ПК
Оставляйте Backend = Auto. Программа учитывает реально свободную RAM непосредственно перед загрузкой модели. При нехватке памяти уменьшаются context и batch. Часть CPU-потоков резервируется для Windows и интерфейса. Для AVX-only процессоров предусмотрен отдельный backend.

Если GGUF физически не помещается в RAM/VRAM, используйте меньшую модель или более сильную квантовку.

Важно: очень сильная квантовка самой модели (например Q2/Q3 и некоторые IQ1/IQ2) может заметно ограничивать качество. Программа показывает диагностику типа GGUF, но не может восстановить веса, уже потерянные при квантовании.

8. ЗАПУСК И ВЫГРУЗКА
«Запустить» загружает выбранную модель.
Во время загрузки отображается индикатор.
Отправка сообщений блокируется до готовности модели.
«Выгрузить» останавливает llama-server и освобождает RAM/VRAM.

9. ЧАТ
«Новый чат» создаёт новую беседу.
Enter — отправить.
Shift+Enter — новая строка.
Кнопка «Копировать» у сообщения копирует его исходный текст целиком.
Ответы поддерживают Markdown-подобное оформление, цветные блоки программного кода и LaTeX-формулы.

10. ЭКСПОРТ ЧАТА
Кнопка «Экспорт» сохраняет текущий чат в один из форматов:
- DOCX — полноценный документ Microsoft Word;
- PDF;
- RTF — совместимый с Word и большинством офисных пакетов;
- TXT UTF-8;
- Markdown (.md);
- HTML;
- JSON — технический переносимый экспорт истории.

11. ВЛОЖЕНИЯ И БАЗА ЗНАНИЙ / RAG 2.0
«＋» добавляет поддерживаемый локальный файл к текущему сообщению.
«База знаний» управляет постоянными локальными материалами программы.

Stage 7G-1 создаёт новый семантический индекс:
- используется отдельная локальная GGUF embedding-модель;
- документы делятся на перекрывающиеся смысловые chunks;
- обычные текстовые PDF извлекаются постранично, поэтому индекс сохраняет номер страницы;
- для каждого chunk вычисляется embedding через локальный llama-server --embeddings;
- текст и метаданные каждого документа сохраняются в Data\RagIndex\doc_*.jsonl;
- векторы float32 сохраняются отдельно в Data\RagIndex\doc_*.vec;
- Data\RagIndex\manifest.json хранит состав индекса, размерность вектора и embedding-модель.

Embedding-модель не обязана совпадать с chat-моделью и обычно должна быть специализированной моделью для embeddings.
Pooling по умолчанию «Auto»: используется настройка embedding-модели. При необходимости можно вручную выбрать mean / cls / last.
Некоторые embedding-модели требуют префиксы вида «passage: » для документов и «query: » для запросов. Программа не угадывает такие правила: их следует задавать согласно документации конкретной модели.

Нельзя смешивать в одном индексе вектора разных embedding-моделей, document prefix или pooling. При смене этих параметров программа потребует очистить и построить RAG-индекс заново.

Stage 7G-2 подключает индекс к чату:
- вопрос пользователя преобразуется той же embedding-моделью, которой создан индекс;
- по cosine similarity выбираются наиболее близкие chunks по всей библиотеке;
- по умолчанию берутся до 24 кандидатов;
- при выбранной совместимой reranker GGUF они повторно ранжируются через локальный llama-server /v1/rerank;
- в контекст chat-модели передаются лучшие фрагменты (по умолчанию 6) с названием документа, страницей и разделом;
- модель получает инструкцию ссылаться на них как [Источник 1], [Источник 2] и т.д.;
- если reranker не запустился, используется semantic ranking;
- если новый vector RAG недоступен, программа откатывается на старый текстовый поиск.

ВАЖНО О СМЕНЕ МОДЕЛЕЙ:
- основную chat-модель (DeepSeek/Qwen/Llama и т.п.) можно менять свободно — библиотека не переиндексируется;
- reranker-модель тоже можно менять свободно;
- embedding-модель задаёт координатное пространство библиотеки и фиксируется после первой индексации;
- пока индекс содержит документы, смена embedding-модели, document prefix и pooling блокируется;
- для перехода на другую embedding-модель нужно очистить RAG-индекс и проиндексировать библиотеку заново;
- query prefix можно менять без перестройки сохранённых document vectors.

Stage 7G-6 добавляет Document Vision — распознавание нетекстового содержания книги:
- отдельная мультимодальная GGUF-модель и соответствующий mmproj выбираются в окне «База знаний»;
- Document Vision использует упакованный Latest llama.cpp runtime с поддержкой libmtmd;
- обычный OCR остаётся источником текста, а Vision дополняет страницу тем, что OCR обычно теряет;
- формулы сохраняются в LaTeX, таблицы реконструируются в Markdown;
- для графиков сохраняются оси, единицы, легенды, тренды и читаемые значения;
- рисунки, оптические/электрические/механические схемы описываются по компонентам, подписям, стрелкам и связям;
- неразборчивые значения должны помечаться как [неразборчиво], а не додумываться;
- Vision-результат добавляется в RAG как отдельный сегмент той же страницы и получает embedding вместе с обычным текстом;
- можно анализировать все страницы или только страницы, которые автоматика считает визуально сложными;
- по умолчанию Vision работает на CPU, чтобы не конкурировать с основной chat-моделью за VRAM; GPU включается отдельно;
- «Сканер PDF» получил кнопку «Vision страница» для проверки одной страницы до индексации всей книги;
- цветной рендер страницы передаётся локальному llama-server через ограниченный media-path; при необходимости есть base64 fallback;
- смена Vision GGUF, mmproj, DPI или режима анализа автоматически делает PDF требующим переиндексации.

Таким образом одна страница может одновременно дать RAG два слоя:
1) Text/OCR — обычный текст;
2) Vision — формулы, таблицы, графики, схемы и другие визуальные сведения.

Ограничение: качество формул, таблиц и графиков зависит от выбранной vision-модели. Document Vision не гарантирует математически точное восстановление неразборчивого оригинала; поэтому исходная страница и номер страницы остаются доступны для проверки.

Stage 7G-5 добавляет восстановление старых сканов перед OCR:
- для OCR-страницы оригинал всегда остаётся контрольным кандидатом;
- OpenCV локально строит несколько вариантов: восстановленный grayscale, adaptive threshold и Otsu;
- перед этим выполняются определение небольшого перекоса текста, deskew, осторожная обрезка пустых полей, выравнивание фона, median denoise и CLAHE-контраст;
- OCR запускается на оригинале и на восстановленных кандидатах;
- лучший вариант выбирается по комбинированной оценке OCR confidence, читаемости символов и объёму полезного текста;
- preprocessing принимается только если достаточно превосходит оригинал; иначе в RAG идёт исходный рендер страницы;
- в «Сканере PDF» отображаются raw/итоговая confidence, выбранный вариант и угол deskew;
- кнопка «До / после» показывает исходную и реально выбранную страницу, а также OCR-текст обоих вариантов;
- изменение настроек восстановления заставляет PDF корректно переиндексироваться.

Ограничение: Stage 7G-5 исправляет плоский старый скан и небольшой геометрический перекос. Сильное нелинейное искривление книжной страницы у корешка, восстановление утраченных символов, специализированное распознавание формул, графиков и сложных таблиц этой стадией не заявляются.

Stage 7G-4 добавляет умный импорт PDF и локальный сканер:
- каждая PDF-страница отдельно проверяется на качество текстового слоя;
- хороший текстовый слой индексируется напрямую без OCR;
- пустой/слишком короткий/повреждённый слой автоматически отправляется в OCR;
- страница рендерится локально через PDFium в grayscale PNG (по умолчанию 300 DPI);
- OCR выполняется локально Tesseract с языками rus+eng и точными tessdata_best-моделями;
- для смешанного PDF разные страницы одного документа могут индексироваться разными способами;
- в manifest сохраняются режим импорта, число OCR-страниц и средняя confidence;
- изменение OCR DPI/языков/min confidence вызывает переиндексацию PDF даже если сам файл не менялся;
- в карточках RAG-источников сохраняются режим извлечения и OCR confidence;
- кнопка «Сканер PDF» позволяет проверить документ постранично до добавления в RAG.

Ограничение Stage 7G-4: OCR распознаёт печатный текст, но не считается надёжным распознавателем математических формул, сложных таблиц и графиков. Их отдельная обработка будет добавлена следующими стадиями. Улучшение тяжёлых старых сканов (deskew/dewarp/denoise/contrast) запланировано для Stage 7G-5.

Stage 7G-3 делает источники проверяемыми:
- под RAG-ответом сохраняются карточки только тех фрагментов, которые действительно были переданы chat-модели;
- номер карточки совпадает со ссылкой [Источник N] в ответе;
- карточка хранит документ, страницу/диапазон страниц, раздел, фрагмент и диагностические оценки поиска;
- «Фрагмент» показывает точный сохранённый текст, который был передан модели;
- «Открыть» запускает исходный файл; для PDF с известной страницей программа сначала пытается открыть file URI с #page=N, а если это не поддерживается системой — открывает сам PDF;
- источники сохраняются в истории чата и остаются после перезапуска программы.

Сканированные PDF без надёжного текстового слоя пока не индексируются в новый RAG. OCR, старые книги, формулы и изображения будут добавляться последующими стадиями 7G.
